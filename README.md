# Green Room — Data-Driven Gaming Trend Analysis

Green Room is a senior graduation project from the College of Computing, Prince of Songkla University
(Phuket Campus). It analyzes real Steam player counts and Twitch stream snapshots (plus a look at the GPU
market) to help streamers and content creators decide **what to play and when to go live**, backed by
measurement instead of guesswork.

A static, no-build-step website (plain HTML/CSS/JS) is generated and powered by a Python data pipeline
(`EDA.py`) that turns raw scraped CSVs into the `data.json` / `insights.json` files the site reads.

## Pages

| Page | File | What it shows |
|---|---|---|
| Overview | `index.html` | Headline stats, "is now a good time to go live" readout, top opportunities, GPU market context |
| Call Sheet | `games.html` | Every tracked game, searchable/filterable, sortable by opportunity/growth/saturation |
| Signal Board | `schedule.html` | Day × hour heatmap of viewer-per-streamer competition, UTC or local-time view, by region |
| Deep Analysis | `insights.html` | The statistics behind the recommendations — correlations, a feature-importance model, predictive validation — sliceable by Year / Month / Week / Day |
| About Us | `about.html` | Team, advisor, and project background |

## Features

- **Interactive charts** — hover for exact values, click to pin, click any game to cross-filter every chart on the page to that title
- **Year → Month → Week → Day drill-down** on Deep Analysis, backed by data computed at each granularity
- **Hybrid search+dropdown** on every filter/select — type to search, arrow keys + Enter to pick
- **Sitewide and per-chart zoom**, with the navbar excluded so it stays legible at any zoom level
- **Light / dark theme toggle**, including a theme-aware heatmap (mint-green in dark mode, blue in light mode)
- Self-updating pipeline: dropping a new month of raw scrapes into `data/raw/` and re-running `EDA.py`
  picks it up automatically — no manual conversion step

```
EDA.py                  # the whole data pipeline: raw CSVs -> data.json / insights.json / chart images
requirements.txt        # Python dependencies for EDA.py
index.html, games.html, # the site itself (static, no build step)
schedule.html,
insights.html, about.html
style.css                # one stylesheet for the whole site (dark + light theme via CSS variables)
js/
  common.js               # shared chrome: nav, zoom, theme toggle, hybrid select, tooltips/pinning
  home.js                 # Overview page
  games.js                # Call Sheet page
  schedule.js              # Signal Board page
  insights.js              # Deep Analysis page (chart rendering, drill-down state)
data/
  raw/                    # scraped CSV dumps, organized by source
  monthly/                # the same data, partitioned into data/monthly/<YYYY-MM>/<category>/*.parquet
  Global_Summary/,         # matplotlib-rendered chart images (legacy/reference; the live site renders
  Visualizations/          # its own interactive charts client-side from data.json/insights.json)
assets/                  # chart images referenced by the site (GPU trend, insight snapshots)
data.json, insights.json  # generated by EDA.py -- what the site actually fetches and renders
```

## Running the pipeline

```bash
pip install -r requirements.txt
python3 EDA.py
```

This reads everything under `data/raw/` and `data/monthly/`, rebuilds `data.json` and `insights.json`,
and regenerates the reference chart images under `data/` and `assets/`. It typically takes under two
minutes on the full dataset.

**Adding a new month of data:** drop the newly scraped CSVs into the matching `data/raw/` subfolder
(`twitch_streams/`, `steam_daily/`, or `gpu_prices/`, same naming convention as the existing files) and
re-run `python3 EDA.py`. Months already converted into `data/monthly/` are left alone, so this is safe to
re-run at any time without double-counting.

## Running the site

It's a static site — any local web server works (needed because the pages `fetch()` `data.json`, which
most browsers block under a plain `file://` URL):

```bash
python3 -m http.server 8000
```

Then open `http://localhost:8000/index.html`.

## Tech stack

- **Pipeline:** Python (pandas, numpy, scipy, scikit-learn, matplotlib, seaborn, pyarrow)
- **Site:** plain HTML/CSS/JS — no framework, no build step, no dependencies to install for the frontend
